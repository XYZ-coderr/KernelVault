1. Architectural Overview

KernelVault (kvault) is an enterprise-grade secure file storage system built on a hybrid architecture combining a low-level Linux Device Driver (GPL v2) and a modern C++20 POSIX user-space storage engine.

Traditional user-space encryption utilities retain master cryptographic keys and cipher block states inside user virtual memory (Ring 3), where they remain vulnerable to ptrace(2) inspection, /proc/$PID/mem scraping, core dump extraction, and unencrypted disk swap partition bleed. KernelVault eliminates these vulnerabilities by enforcing a strict physical memory boundary:

Core Design Principle: Cryptographic transformation boundaries are relegated entirely to non-swappable, kernel-pinned memory pages (Ring 0) via the Linux Crypto API (crypto_alloc_skcipher). Master keys are injected into the kernel via authenticated IOCTL, immediately followed by user-space key wiping via explicit_bzero().

Primary Subsystems

  • Linux Device Driver (driver/kvault_module.c): Exposes /dev/kvault character device with dynamic major number allocation, atomic concurrency single-opener gate (atomic_cmpxchg), and hardware-accelerated AES-256-CBC execution.
  • Move-Only Resource Wrappers (include/UniqueFd.hpp): Enforces deterministic RAII resource reclamation over POSIX file descriptors, guaranteeing automatic invocation of close(2) upon scope exit or exceptions.
  • Advisory File Locking (src/FileLock.cpp): Implements cross-process mutual exclusion using POSIX fcntl(2) with F_SETLK (non-blocking) and F_SETLKW (blocking) semantics.
  • Three-Phase Atomic Commit (src/AtomicFileWriter.cpp): Eliminates file corruption and torn writes across sudden power loss via temporary staging, hardware disk cache writeback (fsync), and POSIX atomic inode swap (renameat2).
  • Deterministic Cryptographic Derivation (src/KeyDerivation.cpp): Standalone PBKDF2-HMAC-SHA256 implementation with 100,000 iterations and constant-time HMAC tag authentication.

2. Linux Kernel Driver Architecture

The kernel module is implemented as an out-of-tree character device driver adhering to strict Linux Kernel Coding Standards. It compiles cleanly against Linux kernel versions 5.4 through 6.x using Kbuild infrastructure.

Driver Lifecycle & Registration

static int __init kvault_init(void)
{
    // 1. Dynamic allocation of Major/Minor device numbers
    alloc_chrdev_region(&dev_num, 0, 1, "kvault");

    // 2. Character device structure initialization
    cdev_init(&kvault_cdev, &kvault_fops);
    cdev_add(&kvault_cdev, dev_num, 1);

    // 3. Sysfs class and device creation for udev auto-population
    kvault_class = class_create(THIS_MODULE, "kvault");
    device_create(kvault_class, NULL, dev_num, NULL, "kvault");

    // 4. Linux Crypto API cipher allocation
    tfm = crypto_alloc_skcipher("cbc(aes)", 0, 0);
    return 0;
}

Single-Opener Concurrency Gate

To eliminate state collisions without introducing scheduler overhead, the driver uses atomic compare-and-swap operations:

static int kvault_open(struct inode *inodep, struct file *filep)
{
    // Atomically test if device is currently acquired
    if (atomic_cmpxchg(&kvault_dev.busy, 0, 1) != 0) {
        return -EBUSY; // Device currently exclusively locked by another process
    }
    return 0;
}

3. IOCTL Interface Specification

The binary interface between user space and kernel space is defined in include/kvault_ioctl.h with magic character 'k'.

IOCTL Macro Direction Payload Type Description
KVAULT_IOCTL_SET_KEY _IOW struct kvault_key_param Copies 256-bit AES key from user space into pinned kernel context.
KVAULT_IOCTL_FLUSH_KEY _IO None Immediately invokes memzero_explicit() on the active kernel key.
KVAULT_IOCTL_SET_IV _IOW struct kvault_iv_param Initializes 128-bit CBC vector for subsequent streaming transformations.
KVAULT_IOCTL_SET_MODE _IOW int (0=Encrypt, 1=Decrypt) Selects synchronous transform operation.
KVAULT_IOCTL_GET_STATUS _IOR struct kvault_status_param Queries lifetime transformed bytes and driver health.
KVAULT_IOCTL_TRANSFORM _IOWR struct kvault_transform_param Transforms memory buffer in-kernel via scatterlist engine.

4. Binary Header Specification

All encrypted records in the vault are framed with a mandatory 96-byte non-padded header:

#pragma pack(push, 1)
struct VaultHeader {
    uint32_t magic;          // 0x00: Constant 'KVLT' (0x4B564C54)
    uint32_t version;        // 0x04: Format version (0x00000001)
    uint8_t  salt[16];       // 0x08: Cryptographic Salt for PBKDF2
    uint8_t  iv[16];         // 0x18: Initial Vector for AES-256-CBC
    uint64_t original_size;  // 0x28: Plaintext size before PKCS#7 padding
    uint64_t payload_size;   // 0x30: Total ciphertext size
    uint8_t  hmac[32];       // 0x38: Constant-time SHA-256 HMAC tag
    uint8_t  reserved[8];    // 0x58: 64-bit alignment padding
};
#pragma pack(pop)

5. CLI Command Reference Manual

The kvault command-line utility provides operational control for vault administration:

kvault init --vault <path>

Initializes a new vault directory structure with 0700 POSIX directory permissions, creates metadata repository, and verifies /dev/kvault accessibility.

kvault encrypt --in <file> --vault <path> [--key <pass>]

Encrypts a plaintext source file into the vault using 64 KiB streaming chunk engine, applies atomic swap guarantees, and records authenticated 96-byte header.

kvault decrypt --file <name> --vault <path> --out <dest> [--key <pass>]

Verifies SHA-256 HMAC authentication tag prior to cipher execution, streams decrypted ciphertext, removes PKCS#7 padding, and atomically writes restored plaintext.

kvault status --vault <path>

Inspects vault records, file sizes, HMAC authentication integrity, and driver session throughput statistics.
